# zerowire v0.4 — hardware test plan

PR #5 lands the Android device-acquisition layer, the foreground service
with a real notification, the Compose UI, and the desktop-linux GTK
window. The unit tests cover all the parts that **don't** need real
USB silicon; this doc is the path to closing the loop on something
plugged in.

> **Status (PR #5 open):** unverified end-to-end. Below is the
> recipe someone with a Pixel + USB stick + a Linux box can run to
> verify the v0.4 work.

## What you need

* An Android phone with USB-host support — Pixel 4 or newer is
  known-good. Most Samsungs work; budget devices sometimes disable
  USB host in the kernel.
* A USB device that's safe to lose mid-test. A cheap thumb drive is
  the canonical case. Avoid anything with bus-powered iso endpoints
  (USB-audio, webcams) — those still hit the documented
  `-EOPNOTSUPP` gap.
* A Linux box on the same LAN, running an unmodified kernel with
  `vhci-hcd` available (`sudo modprobe vhci-hcd` succeeds).
* Either USB-OTG cable or a USB-C dock for the phone side.

## Setup

1. **Build + install the sender.**

   ```bash
   cd android-sender
   ./gradlew assembleDebug
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

2. **Build the desktop GUI** (one of):

   ```bash
   cd desktop-linux-gui
   cargo build --release
   ```

   …or fall back to the CLI receiver from `desktop-linux` if the GUI
   build host is missing X11/Wayland headers.

3. **Open the receiver.** Run `zerowire-gui`. The window shows
   "Idle". Click **Wait for phone** — status flips to "Waiting for
   phone…". A QR is rendered with the local IP + a 12-char pairing
   code.

## Test 1 — pairing

* On the phone, open zerowire. The screen reads "No USB device
  plugged in".
* Tap **Scan pairing QR**. The zxing-embedded camera opens.
* Point at the desktop QR. The phone returns to the main screen with
  the receiver address pre-filled (`<ip>:47823`).
* Verify the pairing code shown on the phone matches the receiver's
  code field.

**Expect:** receiver-address field on the phone reads the desktop's
LAN IP. The Pair button has been dismissed.

## Test 2 — USB attach + permission

* Plug the USB drive into the phone (USB-OTG cable).
* On the phone, the device list renders the new device — vendor:product,
  human kind ("USB drive"), and a **Start sharing** button.
* Tap **Start sharing**. Android shows the system "Use zerowire with
  this USB device?" dialog.
* Tap OK.

**Expect:**

* Notification appears: "Sharing <product> · → <ip>:47823 · N kB/s".
* The receiver-side window flips to "Connected: <phone model>".
* The receiver lists the USB device with its vendor/product IDs.

## Test 3 — actual I/O

* From the desktop terminal, watch `dmesg`:

  ```bash
  dmesg -w
  ```

  You should see a new `usb` device, e.g.:

  ```
  usb 5-1: new high-speed USB device number ...
  usb-storage 5-1:1.0: USB Mass Storage device detected
  scsi host3: usb-storage 5-1:1.0
  ```

* Mount it:

  ```bash
  udisksctl mount -b /dev/disk/by-id/usb-...
  ```

* `dd if=/dev/zero of=$mountpoint/zerowire-write-test.bin bs=1M count=8`
  → completes without errors.
* `dd if=$mountpoint/zerowire-write-test.bin of=/dev/null bs=1M`
  → completes, throughput ~5–15 MB/s on 5 GHz WiFi.
* Unmount with `udisksctl unmount`.

**Expect:** bytes-per-second figure in the phone notification climbs
in sync with the `dd` activity. No `-ETIMEDOUT` errors in `logcat -s zerowire/*`.

## Test 4 — Stop button

* On the phone, tap **Stop**.
* On the desktop, the GUI flips back to "Waiting for phone…" within a second.
* On the phone, the notification flips back to "Ready. No device shared."

**Expect:** clean teardown. No "zombie" notifications. The USB device
remains plugged into the phone but is no longer visible on the desktop.

## Test 5 — Unplug mid-session

* Restart sharing (Test 2).
* While the desktop is reading bytes, physically yank the USB cable
  from the phone.
* The phone notification flips to "zerowire error: USB device gone".
* The desktop GUI shows "Error: …" within 1 frame and offers to
  restart.

**Expect:** no crash on either side; no lingering `vhci-hcd` ports.

## Test 6 — Stop from notification

* Restart sharing.
* Swipe down the Android notification shade and tap the **Stop**
  action on the zerowire notification.

**Expect:** identical teardown to Test 4 — the in-app and
notification Stop buttons must be equivalent.

## Known gaps to file as separate bugs

* Iso transfers (USB audio / webcams) reply `-EOPNOTSUPP` cleanly.
  Documented limitation, not a regression.
* Some phones report `is_hid` for composite devices incorrectly;
  the UI shows "USB device" rather than the specific class.
* The bytes/sec counter is only wired through the usbip ATTACH path.
  HID-fast-lane sessions show 0 B/s in the notification — to be
  fixed in v0.4.1.
